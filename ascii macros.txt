################################################################################
# IMPLEMENTATION NOTES
################################################################################
#
# Priority for implementation:
#
# TIER 1 — Essential (blocks basic code generation):
#   <. .>  for ⟨ ⟩  (anonymous constructors — used constantly)
#   .      for ·    (tactic focusing — used in every proof)
#   up     for ↑    (coercions — used in every Nat/Int interaction)
#   comp   for ∘    (function composition)
#   ><     for ×    (product types)
#
# TIER 2 — Common in proofs:
#   |-     for ⊢    (turnstile)
#   ===    for ≡    (definitional equality)
#   ~=     for ≈    (approx)
#   ~-     for ≃    (equiv)
#   ~==    for ≅    (iso)
#   subst_arrow for ▸
#
# TIER 3 — Mathlib notation (only if using Mathlib):
#   mem/!mem/cup/cap/subset/etc.
#   sqcup/sqcap/iSup/iInf
#   oplus/otimes
#   lhd/rhd (normal subgroups)
#
# TIER 4 — Rare / domain-specific:
#   partial/nabla/integral
#   aleph/ell
#   sharp/flat/natural
#
# Greek letters and subscripts are identifier-level and don't need macros —
# just use the ASCII spelling (alpha, beta, _1, _2, etc.).
#
# Example Lean 4 macro for anonymous constructor brackets:
#
#   notation "<." xs ">" => (by exact ⟨xs⟩)    -- or use Lean macro system
#
# A more robust approach: patch the Lean parser to accept ASCII alternatives,
# or use a preprocessing step that replaces ASCII tokens with Unicode before
# feeding to Lean.
